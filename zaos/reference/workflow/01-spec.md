# Phase 1-2 : Compréhension & Spécification

## Objectif
Transformer une demande vague en une spec claire et validée.

## Checklist

### Compréhension (Phase 1)
- [ ] La demande a été écoutée et reformulée
- [ ] Les zones floues ont été clarifiées par des questions
- [ ] Le type de tâche est identifié (feature, bug, refactoring, recherche)
- [ ] L'utilisateur a validé la reformulation

### Spécification (Phase 2)
- [ ] La spec utilise le template `feature-spec.md`
- [ ] L'objectif est décrit en termes utilisateur (pas technique)
- [ ] Le comportement attendu est décrit (inputs → outputs)
- [ ] Les contraintes sont listées
- [ ] Les critères de "done" sont définis
- [ ] Le Researcher a été consulté si des infos manquaient
- [ ] L'utilisateur a validé la spec

## Questions type à poser en Phase 1
- "Quel est le résultat attendu du point de vue de l'utilisateur ?"
- "Y a-t-il des contraintes techniques ou de design ?"
- "Comment ça doit interagir avec ce qui existe déjà ?"
- "Quel est le cas d'erreur le plus probable ?"
